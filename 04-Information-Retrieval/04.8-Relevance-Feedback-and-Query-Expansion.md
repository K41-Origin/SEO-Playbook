# 04.8 — Relevance Feedback & Query Expansion

## 1. Purpose and Scope

A query is an imperfect expression of an information need. A user may not know the collection's vocabulary, may omit useful concepts, or may discover what they actually need only after seeing the first results. Relevance feedback and query expansion are methods for improving retrieval by revising the query representation or adding useful terms. [1]

This topic covers:

- Explicit, implicit, and pseudo-relevance feedback.
- Iterative feedback and query reformulation.
- The Rocchio algorithm in the Vector Space Model.
- Probabilistic relevance feedback.
- Local and global query expansion.
- Vocabulary resources, thesauri, co-occurrence, and query-log-based suggestions.
- Query drift, ambiguity, evaluation, and practical safeguards.

The scope is **general Information Retrieval theory**. It does not define SEO keyword research, search-intent classification, or the internal query systems of Google, Bing, or another proprietary search engine.

## 2. Core Concepts

### 2.1 Relevance Feedback

**Relevance feedback (RF)** uses evidence about retrieved documents to revise a query or retrieval representation. In the classic interactive process:

1. The user submits an initial query.
2. The system retrieves an initial result set.
3. The user judges some results as relevant or non-relevant.
4. The system uses those judgments to update the query representation.
5. The system retrieves again with the revised representation.

The cycle can repeat. The user does not need to predict every useful term before seeing the collection; they can judge examples and let the system use those judgments to refine retrieval. [1][2]

Feedback can also expose an evolving information need. A user may begin with a broad request, inspect documents, and then realize that a particular subtopic or interpretation is what they actually want. That is a change in the information need—not merely a spelling correction. [1]

### 2.2 Query Reformulation vs. Query Expansion

These terms are related, but they are not interchangeable:

- **Query reformulation** is the broader act of changing a query representation. It can replace terms, remove terms, reweight terms, add constraints, or change the query structure.
- **Query expansion** adds terms or phrases to the original query or its representation, often to cover alternate vocabulary or related concepts.
- **Relevance feedback** is a source and process for updating retrieval based on judgments about documents. Its output may expand or reweight a query, but it is not limited to adding terms.

A query can be reformulated without being expanded. For example, replacing an ambiguous term with a more precise one is reformulation, not necessarily expansion. [1]

### 2.3 Local vs. Global Analysis

The textbook distinction is useful:

| Method | Evidence used | Typical approach |
|---|---|---|
| **Local analysis** | Documents retrieved for the current query | Relevance feedback and pseudo-relevance feedback |
| **Global analysis** | Collection-wide vocabulary resources or patterns, independent of the current result set | Thesaurus-based expansion, controlled vocabularies, automatically induced term associations, and query-log mining |

Local methods adapt to the current query's result set. Global methods use knowledge or statistics that exist beyond that specific result set. These methods can also be combined. [1]

## 3. Types of Relevance Feedback

### 3.1 Explicit Feedback

Explicit feedback is a direct relevance judgment supplied by a user—for example, marking a result as relevant or non-relevant, or assigning a graded relevance label.

**Strengths:**

- The system receives a clearer signal about the user's judgment than it gets from passive behavior.
- Positive and negative judgments can both be used.
- Feedback can clarify which interpretation of an ambiguous query the user intends.

**Limitations:**

- Users must spend time judging results.
- Users may be unwilling to interact repeatedly.
- A small or unrepresentative set of judgments can mislead the update.
- Relevance is task-dependent; two users can reasonably judge the same document differently. [1]

Explicit judgments are evidence about the judged documents and task. They are not universal truth labels for every user or query.

### 3.2 Implicit Feedback

Implicit feedback infers possible preferences or relevance from behavior rather than asking users to label documents directly. Examples include clicks or other interaction signals. [1]

Implicit feedback is easier to collect at scale, but its interpretation is weaker. A click is an observed action, not a direct statement that the document satisfied the information need. The textbook notes that click-based approaches rely on assumptions about the result summaries users saw and used when deciding what to click. [1]

Therefore:

- A click should not automatically be treated as a positive relevance judgment.
- Lack of a click does not automatically prove irrelevance.
- Interaction data needs task, interface, and exposure context before it can be interpreted.
- Aggregated behavior can be useful evidence, but it is not equivalent to explicit assessor judgments.

### 3.3 Pseudo-Relevance Feedback (PRF)

**Pseudo-relevance feedback**, also called **blind relevance feedback**, automates local feedback by assuming that the top-ranked documents from an initial retrieval are relevant. The system then extracts terms or features from those documents and uses them to revise the query—without asking the user to label the documents. [1]

A typical process is:

1. Retrieve an initial ranked list.
2. Select the top (k) documents.
3. Treat those documents as provisionally relevant.
4. Extract candidate terms or representations from them.
5. Expand or reweight the query.
6. Run retrieval again.

The word *pseudo* matters. The system has not received relevance judgments; it has made an assumption based on its own first-pass results.

PRF can improve retrieval when the initial top results are genuinely representative. It can also amplify an early mistake. If the initial results are dominated by one unintended interpretation, the expansion may reinforce that interpretation and push the query away from the user's actual need. This failure is known as **query drift**. [1]

### 3.4 Comparison

| Feedback type | Where the evidence comes from | User interaction | Main risk |
|---|---|---|---|
| Explicit | Direct relevance judgments | Required | Sparse, costly, or inconsistent judgments |
| Implicit | Observed interaction behavior | Usually passive | Behavior is an imperfect proxy for relevance |
| Pseudo-relevance | Top-ranked initial results | Not required | Initial retrieval errors are reinforced |

These are not three interchangeable labels for the same process. They differ in the source and reliability of the evidence used to update retrieval.

## 4. Rocchio Algorithm

### 4.1 What It Does

The **Rocchio algorithm** is a classical relevance-feedback method for the Vector Space Model. It updates the query vector by combining the original query with the centroid of judged-relevant documents and subtracting the centroid of judged-non-relevant documents. [1][2]

The intuition:

- Move the query toward the vocabulary profile of relevant documents.
- Move it away from the vocabulary profile of non-relevant documents.
- Keep some influence from the original query so the update does not completely replace the user's starting point.

### 4.2 Formula

A common Rocchio update is:

[
ec{q}_{new} =
alpha ec{q}_{0}
+ eta rac{1}{|D_r|}sum_{ec{d}_j in D_r}ec{d}_j
- gamma rac{1}{|D_{nr}|}sum_{ec{d}_j in D_{nr}}ec{d}_j
]

Where:

| Symbol | Meaning |
|---|---|
| (ec{q}_{0}) | Original query vector |
| (ec{q}_{new}) | Revised query vector |
| (D_r) | Set of documents judged relevant |
| (D_{nr}) | Set of documents judged non-relevant |
| (alpha) | Weight retained for the original query |
| (eta) | Weight assigned to the relevant-document centroid |
| (gamma) | Weight assigned to the non-relevant-document centroid |

The centroids are average document vectors, not raw sums. Averaging prevents a class with more judged documents from automatically dominating solely because it contains more vectors. The parameters control the balance between the original query and feedback evidence. [1]

### 4.3 Interpreting the Parameters

- Higher (alpha) preserves more of the original query.
- Higher (eta) gives more influence to judged-relevant documents.
- Higher (gamma) gives more influence to judged-non-relevant documents.
- Setting (gamma=0) removes negative feedback from the update.

The textbook discusses settings in which positive feedback receives more weight than negative feedback, and notes that some systems use only positive feedback. Parameter values are model choices, not universal constants. [1]

### 4.4 Negative Weights and Clipping

Subtracting the non-relevant centroid can produce negative term weights. In the classical Rocchio treatment described by Manning et al., negative weights are ignored by setting them to zero before the revised query is used for retrieval. [1]

This matters because a negative vector component is not automatically equivalent to a Boolean NOT clause. It is a negative weight in a vector representation. Query parsers and retrieval implementations may handle negative terms differently.

### 4.5 Conceptual Example

Suppose the initial query is **“jaguar speed”**.

The first result set contains:
- Relevant documents about the animal's running speed.
- Non-relevant documents about the Jaguar car brand.

If the user marks animal-related documents as relevant and car-related documents as non-relevant, Rocchio can increase the weights of terms that characterize the relevant documents and reduce the weights of terms associated with the non-relevant set.

The example is illustrative, not a claim that Rocchio can always resolve polysemy. If the judged documents are mixed, sparse, or poorly representative, the centroid can still encode the wrong direction.

## 5. Probabilistic Relevance Feedback

Relevance judgments can also update term probabilities rather than query-vector centroids.

In a binary term-incidence setting, let:

- (R=1) mean a document is judged relevant.
- (x_t=1) mean term (t) occurs in a document.
- (p_t=P(x_t=1mid R=1)) be the probability that term (t) occurs in a relevant document.
- (u_t=P(x_t=1mid R=0)) be the probability that term (t) occurs in a non-relevant document.

Judged documents provide observations for estimating these probabilities. Terms that occur more often in relevant than non-relevant documents can receive stronger positive evidence. [1][3]

The Binary Independence Model (BIM) discussed in [04.7](04.7-Probabilistic-Information-Retrieval-Models.md) uses relevance and non-relevance term probabilities to derive log-odds term contributions. Relevance feedback supplies judgments that can help estimate or update those probabilities. The connection is direct, but the methods remain conceptually distinct:

- Rocchio updates a vector-space query using document centroids.
- Probabilistic feedback updates term evidence or probability estimates using relevance classes.
- BM25 is a probabilistic weighting model, but applying user feedback to a retrieval system is not automatically the same thing as changing BM25's standard formula.

Sparse judgments can produce unstable estimates, including zero or one probabilities. Smoothing or pseudocounts may be needed to avoid extreme estimates and undefined log-odds calculations. See [04.7](04.7-Probabilistic-Information-Retrieval-Models.md) for the underlying BIM probability and smoothing concepts. [1][3]

## 6. Query Expansion Methods

Query expansion adds terms or phrases that may help retrieve relevant documents expressed in different vocabulary. It can be driven by local feedback, global resources, or a combination. [1]

### 6.1 Controlled Vocabulary and Thesaurus

A controlled vocabulary maps concepts to preferred terms and may include synonyms, broader terms, narrower terms, or related concepts. A thesaurus can provide candidate expansion terms without requiring the system to infer every relationship from the current result set. [1]

Examples include:
- Domain-specific controlled vocabularies maintained by subject experts.
- Manually curated thesauri.
- Lexical databases such as WordNet.
- Structured subject-heading systems.

A synonym is not automatically a safe replacement. Word sense and domain context matter. For example, expanding *jaguar* with terms related to cars and animals at the same time may reduce precision rather than improve retrieval.

### 6.2 Automatically Induced Term Associations

A system can derive term associations from a document collection. One classical approach uses term co-occurrence: terms that appear together in documents or passages are treated as potentially related. More elaborate approaches can use grammatical relations or latent semantic representations. [1]

But co-occurrence is evidence of association, not proof of synonymy or conceptual equivalence. Terms may co-occur because they are contrasting, causally related, part of the same event, or simply frequent in the same domain.

Automatic thesauri can therefore introduce:
- False-positive associations.
- Missing useful relationships.
- Ambiguous expansions.
- Collection-specific vocabulary that does not generalize.

The textbook gives the example of an ambiguous query such as **“Apple computer”** being expanded with terms associated with the fruit, illustrating how statistical association can inject the wrong sense. [1]

### 6.3 Query-Log-Based Reformulation

Query-log mining uses query reformulations made by other users to suggest alternatives or related queries. The approach can reveal common reformulation paths, but it depends on access to sufficiently large and relevant query logs. A reformulation sequence is evidence of observed behavior—not a guarantee that every suggested query expresses the same information need. [1]

### 6.4 Local Expansion from Retrieved Documents

Local expansion extracts candidate terms from the initial result set or from documents judged relevant. This can adapt the query to the collection's vocabulary and the current topic. It is also vulnerable to query drift when the initial results contain irrelevant themes. [1]

### 6.5 Weighting Added Terms

Expansion terms do not have to receive the same weight as original query terms. A system can preserve the original query terms at higher weights and assign lower weights to added terms. This reduces the chance that weak associations overwhelm the user's initial intent. [1]

A practical expansion policy can also:
- Limit the number of added terms.
- Require minimum evidence or association strength.
- Prefer domain-appropriate vocabulary.
- Exclude terms that introduce conflicting senses.
- Keep the original query available as a baseline.

These are design controls, not guarantees that expansion will improve every query.

## 7. Feedback and Expansion: End-to-End Workflow

A general workflow can be represented as:

[
q_0 ightarrow 	ext{initial retrieval} ightarrow 	ext{evidence}
ightarrow 	ext{query update} ightarrow 	ext{second retrieval}
]

The evidence step depends on the selected method:

| Stage | Explicit feedback | Implicit feedback | Pseudo-relevance feedback | Global expansion |
|---|---|---|---|---|
| Initial query | User query | User query | User query | User query |
| Evidence | User relevance labels | Interaction signals | Top-ranked documents | Vocabulary resources or collection-wide statistics |
| Update | Reweight or add terms | Infer term/document preference | Treat top results as provisionally relevant | Add suggested terms or reformulations |
| Retrieval | Run revised query | Run updated representation | Run expanded query | Run expanded/reformulated query |
| Main control | Judgment quality | Behavioral interpretation | Initial-result quality | Association and sense quality |

This is a conceptual workflow. Real systems may combine methods, apply expansion only under selected conditions, or use a different internal representation. [1]

## 8. When Relevance Feedback Works—and When It Does Not

Feedback is more likely to help when:

- The initial query retrieves at least some documents close to the intended information need.
- Relevant documents share enough vocabulary or representation features.
- The judged documents represent the intended topic rather than one accidental subtopic.
- There are enough useful judgments to estimate a meaningful update.
- The collection's vocabulary overlaps with the terms available to the query.

Feedback alone is less likely to solve:

- **Severe vocabulary mismatch:** the initial query retrieves no useful documents because the collection uses entirely different terminology.
- **Misspellings or tokenization mismatch:** the initial query cannot reach relevant documents in the first place.
- **Cross-language mismatch:** a lexical vector built in one language may not represent documents in another language.
- **Multimodal relevance classes:** relevant documents may form several distinct clusters rather than one coherent centroid.
- **Ambiguous or disjunctive needs:** a single centroid may blur multiple legitimate interpretations or subtopics. [1]

More feedback is not automatically better. Additional judgments can help when they add representative evidence, but can hurt when they reinforce a narrow or incorrect interpretation.

## 9. Query Drift and Other Failure Modes

| Failure mode | What happens | Mitigation |
|---|---|---|
| Query drift | Added terms move retrieval away from the intended information need. | Preserve original terms, constrain expansion, inspect candidate terms, and compare with the baseline. |
| Ambiguous association | A term adds vocabulary from the wrong sense. | Use context-sensitive or domain-specific resources; reject ambiguous candidates. |
| Feedback sparsity | Too few judgments produce unstable term estimates. | Avoid aggressive updates; collect more representative judgments where feasible. |
| One-cluster assumption | Relevant documents belong to several distinct vocabulary groups. | Segment the need or use multiple prototypes rather than forcing one centroid. |
| No useful initial results | Local feedback has no reliable relevant evidence to learn from. | Use spelling correction, vocabulary tools, or global resources before local feedback. |
| Implicit-signal bias | Clicks or other behavior are mistaken for direct relevance labels. | Interpret behavior with exposure and interface context; do not equate clicks with relevance. |
| Expansion overload | Too many weak terms dilute the original query. | Limit terms and give added terms lower weights. |
| Opaque reformulation | Users cannot tell why results changed. | Expose suggestions or explain the main terms and evidence behind the update. |

The safeguards are practical design recommendations derived from the documented failure modes; they do not eliminate the underlying uncertainty. [1]

## 10. Evaluating Feedback and Expansion

A feedback method should be compared with a clear baseline, not declared successful because the revised query looks more sophisticated.

A defensible evaluation should:

1. Define the retrieval task and information need.
2. Record the original query and baseline result set.
3. Specify the feedback source and judgment protocol.
4. Keep the collection, index, and evaluation conditions controlled.
5. Compare the revised method using appropriate IR metrics.
6. Avoid evaluating only on documents already used as feedback.
7. Inspect query drift, topic coverage, and the quality of newly retrieved documents.
8. Where user interaction is part of the task, consider user utility such as time to find useful information.

The evaluation design matters. If documents used as feedback are also counted as newly retrieved successes, the measured improvement can be inflated because the system has already been told those documents are relevant. Manning et al. discuss this leakage problem and the difficulty of comparing feedback and non-feedback runs fairly. [1]

Use [04.11](04.11-Relevance-Assessment-and-Evaluation-Frameworks.md) for relevance assessment and evaluation design, and [04.12](04.12-Information-Retrieval-Evaluation-Metrics.md) for formal IR metric definitions when those topics are documented.

## 11. Relevance to SEO — Evidence Boundary

Relevance feedback and query expansion explain how an IR system can use judgments, interaction evidence, or vocabulary resources to improve retrieval for an information need. They do **not** provide a recipe for manipulating organic search rankings.

Keep these boundaries clear:

- **Domain 04.8** owns relevance feedback and query expansion as IR methods.
- **Domain 05 — Keyword & Search Intent** owns SEO keyword research, query discovery, and search-intent analysis.
- **Domain 03** owns search-engine ranking systems and ranking behavior.
- **Domain 14** owns site-owner Search Console performance analysis.

Search Console query data, keyword tools, and SEO query clustering are not automatically relevance feedback. They may provide useful observations for SEO analysis, but that does not make them document-level relevance judgments or evidence that a search engine uses Rocchio, PRF, or a particular expansion algorithm.

Likewise, adding every synonym or co-occurring term to a page is not the same as IR query expansion. Query expansion changes how a retrieval system represents or processes a query; it does not establish that content should repeat or indiscriminately accumulate those terms.

No claim is made here that Google Search uses Rocchio, pseudo-relevance feedback, a specific thesaurus, or any formula described in this document. General IR literature explains methods and assumptions—not proprietary production implementation.

## Key Takeaways

- Relevance feedback uses evidence about retrieved documents to revise retrieval.
- Explicit feedback comes from direct judgments; implicit feedback comes from behavior; pseudo-relevance feedback assumes top-ranked results are relevant.
- Query reformulation is broader than query expansion. Relevance feedback is a process that can produce either.
- Local methods use the current result set; global methods use collection-wide vocabulary resources or patterns.
- Rocchio moves a query vector toward relevant-document centroids and away from non-relevant-document centroids.
- Probabilistic feedback updates term evidence using relevance-class statistics and connects directly to the BIM foundations in 04.7.
- Query expansion can improve recall, but ambiguous associations can reduce precision or cause query drift.
- Pseudo-relevance feedback is not user feedback. It is an automated assumption about the initial top results.
- Evaluation must avoid counting feedback documents as independent retrieval gains.
- IR query expansion is not SEO keyword stuffing and does not reveal a proprietary search engine's internal algorithm.

**Bottom line:** Feedback helps a retrieval system learn from evidence after the first search. Expansion helps it cover vocabulary the original query missed. Both can improve discovery—and both can confidently make the wrong search even worse when the evidence is bad.
