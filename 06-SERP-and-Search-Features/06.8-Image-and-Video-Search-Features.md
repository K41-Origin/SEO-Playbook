# 06.8 — Image & Video Search Features

**Domain:** [06 — SERP & Search Features](README.md)  
**Topic:** 06.8 — Image & Video Search Features

Image and video search features let users discover visual and audiovisual content through search interfaces. They appear in more than one place: image or video tabs, dedicated search modes, visual modules inside general web results, and previews attached to other result types.

This topic documents those visible experiences. It does not turn into an image-optimization checklist, video-production guide, or structured-data implementation manual. Those jobs have canonical owners elsewhere. A thumbnail appearing in a result is a presentation detail—not proof that the page has earned some mysterious SEO badge.

Google-specific behavior is attributed to Google. Do not assume that Bing or another engine uses the same labels, layouts, or eligibility rules.

## 1. Image Search Features

### 1.1 Google Images and image results

Google Images is a visual search experience in which users browse image results for a query. Image results may expose a thumbnail, a source page or website attribution, and other contextual information. Selecting a result can open a larger preview and provide a route to the page where the image appears. The exact interface and available actions can change across devices and product versions. [1][2]

An image result is not the same thing as an image file being presented as an ordinary web result. The image experience connects a visual asset with contextual information and, where available, the page that hosts or discusses it. Google's documentation emphasizes that both the image and its landing page contribute to how the image may be understood and shown. [1]

### 1.2 Image modules in general web results

Images can also appear within the main web-results experience—for example, as image previews associated with a text result or as a grouped visual module. These placements are not the same as the dedicated Google Images experience. Google explicitly distinguishes text-result images, Google Images, and Discover as separate visual discovery surfaces, even though some image-discovery recommendations apply across them. [1]

A visible image preview in a web result should therefore be recorded as part of that result's presentation. It should not automatically be classified as a Google Images result, nor treated as evidence that the source image has a dedicated image-result placement.

### 1.3 Image result context and attribution

The visual asset is only one part of an image result. The surrounding page, its textual context, captions, image title information, and source attribution can help users understand what the image represents and where it came from. Google's image guidance says it uses page content, captions, image titles, alt text, and computer-vision systems to understand image subject matter. [1]

The result interface may not expose every contextual signal used by the search engine. Do not infer that a displayed label, thumbnail crop, or source link reveals the complete image-understanding process.

## 2. Visual Search and Google Lens

Google Lens lets users start a search with an image rather than relying only on a text query. Users can submit an image, use an image URL, or invoke visual search from supported browser and product contexts. Google's documented result types can include information about objects in the image, similar images, and websites containing the image or a similar one. [3]

This is a different query-entry path from typing a conventional text query into Google Search. The result experience can combine visual matching with text-based exploration; it should not be reduced to a reverse-image lookup that only finds exact copies.

Keep the boundary clear:

- **Google Images:** users browse image results for a query.
- **Google Lens:** users use an image or visual selection as the starting point for a search.
- **Image previews in web results:** visual elements attached to results in the main web-search experience.

These experiences are related, but they are not interchangeable product names. Lens entry points and result layouts can differ by device, browser, and Google product context. [2][3]

Detailed query-refinement controls and multi-step exploration behavior belong to 06.10. This section covers the visual-search experience and the kinds of results Google documents.

## 3. Video Search Features

### 3.1 Video results across Google surfaces

Google says videos can appear in several places, including the main Search results page, Video mode, Google Images, and Google Discover. These are distinct presentation contexts; a video appearing in a general web result does not mean the user is viewing the dedicated Video mode. [4]

**Video mode** is the video-focused search experience. It helps users browse video results for a query, while video-related results can also be surfaced in the main web-results experience. The visible result format may include a thumbnail, title, source or publisher, duration, and other contextual details. This list describes common observable fields, not a guaranteed universal card specification. Google's current documentation focuses on video eligibility and supported enhancements rather than promising a fixed UI layout. [4][5]

### 3.2 Video thumbnails and previews

A video thumbnail is a visual representation of the video used in search presentation. Google requires a valid thumbnail for video features and documents ways a publisher can provide thumbnail information. A video preview is different: Google may select a few seconds of the video to display as a moving preview when the video files can be fetched. [4]

Do not confuse these three things:

- **Thumbnail:** a still image representing the video.
- **Video preview:** a short moving excerpt selected for display.
- **Watch page:** the page where the user can actually watch the video.

Google's video guidance distinguishes the watch-page URL, player URL, and video-content URL. A search result generally directs users to the watch page; the presence of a thumbnail does not mean the video file itself is exposed as the result destination. [4]

### 3.3 Key moments and video chapters

**Key moments** help users navigate to important segments within a video. Google may detect segments automatically. Publishers can also provide segment information through supported structured data, or—when the video is hosted on YouTube—through timestamps in the video description. [5]

For embedded videos or video platforms, Google documents two relevant structured-data approaches:

- `Clip` identifies specific segments with start and end times and labels.
- `SeekToAction` describes the timestamp pattern in a URL so Google can identify and link to points in the video.

YouTube descriptions can also provide timestamp labels for eligible videos. Google says it may automatically identify key moments for YouTube videos, so manually supplied timestamps are not the only possible source. Availability of the documented `SeekToAction` approach is language-dependent; do not generalize its supported-language list to every key-moment method. [5]

Key moments are a navigation enhancement, not a separate video hosting product and not a guarantee that every video will receive chapter links. Google can choose whether to display them.

### 3.4 Live badges

Google documents a **LIVE** badge for eligible livestream videos. Its guidance associates this presentation with `BroadcastEvent` structured data and recommends notifying Google through the Indexing API when the stream starts, stops, or relevant markup changes. [5]

A LIVE badge is a visible status indicator, not proof that the stream is accurate, authoritative, or available indefinitely. It should only be described as live when the interface actually shows the badge or the source explicitly identifies the stream as live.

## 4. Image and Video Result Presentation: What to Observe

When documenting a visual result, capture the fields that are actually visible rather than assuming every card follows one template.

| Element | Image-oriented result | Video-oriented result |
|---|---|---|
| Visual preview | Image thumbnail or preview | Video thumbnail; sometimes a moving preview |
| Source context | Website, source page, or image context | Publisher, video platform, or watch page |
| Title or description | May be drawn from the image's surrounding page and metadata | Video title and descriptive information |
| Additional navigation | Open image, visit source page, or continue visual exploration | Open watch page, enter Video mode, or jump to a key moment where available |
| Temporal information | Usually not central to a generic image result | Duration, upload/publication context, or LIVE status may be shown |

This is an observation framework, not a Google-published universal schema. The exact fields and interactions depend on the result surface and interface version. [1][4][5]

## 5. Eligibility and Display Are Not the Same Thing

Google's documentation describes technical and content conditions that affect whether images and videos can be discovered, indexed, and considered for search features. It does not promise that every accessible asset will appear, or that every eligible video will receive a video enhancement. [1][4]

For video features, Google documents requirements such as an indexed watch page, a video embedded on that page, a valid thumbnail at a stable URL, and the ability for Google to fetch relevant video content for certain features. An indexed page alone does not prove that its video has also been indexed. [4]

For images, Google explains that image discovery and indexing have requirements that differ from ordinary HTML text. The image's embedding method, accessibility to crawlers, landing-page context, and available metadata can affect discovery and presentation. [1]

These are eligibility and discovery considerations. They are not ranking guarantees, and this topic does not prescribe implementation steps. See Domain 10 for technical controls and structured-data implementation.

## 6. Structured Data: A Presentation Connection, Not This Topic's Owner

Structured data can provide Google with information about images and videos and may support certain enhanced presentations. For video, Google's documentation describes `VideoObject` and related types such as `Clip`, `SeekToAction`, and `BroadcastEvent`. For image-related rich results, supported structured-data types have their own requirements. [5][6]

The distinction matters:

- Domain 06.8 explains the visible image and video features and what their displayed elements mean.
- Domain 06.3 owns the general concept of rich results and structured-data search appearance.
- Domain 10 owns implementation, validation, and technical troubleshooting of structured data.

Valid markup does not force Google to display a particular feature. Google's video documentation explicitly says that adding markup does not guarantee a specific video feature in Search. [5]

## 7. Google Images, Video Mode, Discover, and Lens Are Different Surfaces

Visual content can travel through multiple Google products. Similar thumbnails do not make those products one feature.

| Surface | User entry point | Main experience | Boundary |
|---|---|---|---|
| Google Images | Image search query | Browse image results | Dedicated image-search experience |
| Image previews in web results | Conventional web query | Images supplement web-result presentation | Not the same as the Images tab |
| Google Lens | Image, camera view, or visual selection | Search using visual input; results may include objects, similar images, and related websites | Visual query entry and discovery |
| Video mode | Video-oriented query or Video tab | Browse video results | Dedicated video-search mode |
| Video results in main Search | Conventional web query | Video result or video enhancement within general results | Not necessarily Video mode |
| Google Discover | Personalized content feed | Content discovery without requiring a submitted search query | Not a query-driven SERP |

Google explicitly lists several destinations for video content and distinguishes image discovery surfaces. Its Search Help documents Lens as image-based search. Discover is a separate discovery experience, not a search-results tab. [1][3][4]

## 8. Observing and Auditing Image & Video Features

A useful observation record should capture:

1. Search engine and exact surface: Google Images, Video mode, main Search, Lens, or Discover.
2. Exact text query or visual input, where applicable.
3. Country/region, language, device, browser, and observation date/time.
4. Whether the result is an image result, an image preview attached to a web result, a video result, or a video enhancement.
5. Visible thumbnail/preview, title, source attribution, duration, and temporal or LIVE labels.
6. Whether a larger image preview, video preview, related-image set, or source-page link is available.
7. Whether video key moments or timestamp navigation appears.
8. The destination URL and whether it leads to an image asset, source page, or video watch page.
9. Any obvious account, device, or product context that may affect the observed interface.

For comparisons, keep the query, visual input, location, language, device, and product surface consistent. A screenshot proves what appeared in that observation—not universal availability, complete indexing, or hidden ranking logic.

## Key Takeaways

- Google Images, image previews in web results, and Google Lens are related but distinct experiences.
- Video content can appear in main Search, Video mode, Google Images, and Discover; these surfaces are not interchangeable.
- Thumbnails, moving previews, watch pages, key moments, and LIVE badges represent different presentation elements.
- Key moments can be detected automatically or informed through supported timestamp and structured-data methods; display is not guaranteed.
- Google documents specific discovery and indexing conditions for images and videos, but eligibility does not guarantee visibility.
- Structured data can help describe media and support eligible enhancements; it does not force a search feature to appear.
- Technical implementation belongs in Domain 10, not here. This page owns the visible feature and its behavior.
