# 10.5 — XML Sitemaps & URL Discovery Support

[← Domain 10 — Technical SEO](README.md)

An XML sitemap is a machine-readable list of URLs that a site makes available to search engines. It can help communicate which URLs a publisher considers important and when selected resources were last meaningfully modified. Submission is a discovery hint, not a command to crawl, index, or display every listed URL. [1]

## 1. When sitemaps are useful

Sitemaps can be particularly useful for large sites, new sites with few external discovery paths, sites with complex URL inventories, and sites containing specialized media or news content. Google notes that small, well-linked sites may be able to expose their pages without a sitemap; a sitemap can still provide operational inventory and monitoring value. [1]

A sitemap should represent the site's intended canonical URL inventory, not every URL the application can generate. Avoid including URLs that redirect, return errors, are blocked from crawling, carry noindex directives, or are duplicates of a preferred URL unless a specific documented use case applies. [1][2]

## 2. Protocol structure and limits

The Sitemaps protocol defines XML elements including `<urlset>`, `<url>`, `<loc>`, and optional metadata such as `<lastmod>`. Large inventories can be split into multiple sitemap files and referenced by a sitemap index. Protocol constraints include limits on the number of URLs and uncompressed file size per sitemap; verify the current specification before designing partitions. [3]

Use absolute, fully qualified URLs. Keep each sitemap's URL scope consistent with the protocol and search-engine requirements. Treat `lastmod` as a factual assertion: update it when the page's significant content changes, not on every crawl or deployment if the content did not materially change. Google may use the value when it is consistently and verifiably accurate. [1][3]

## 3. Discovery and submission

A sitemap can be discovered through a reference in robots.txt or submitted through supported search-engine tools. Submission does not guarantee that every listed URL will be fetched or indexed. Google explicitly states that sitemap inclusion does not guarantee indexing or increase ranking. [1][4]

Sitemap processing reports are not index coverage reports. A submitted URL count, discovered URL count, crawled URL count, and indexed URL count are different measurements. Interpret each report according to its documented meaning.

## 4. Generation and maintenance

Generate sitemaps from the canonical content/URL inventory where possible rather than maintaining fragile hand-written lists. Rebuild or update them when resources are published, materially updated, redirected, removed, or canonicalized. For very large sites, partition by content type, section, update cadence, or another operationally useful dimension, and use a sitemap index to reference the files. [1][3]

A robust validation process checks:

- XML well-formedness, encoding, and required elements.
- Absolute URL format and correct host/protocol.
- URL response status and redirect behavior.
- Canonical target and indexability alignment.
- Robots.txt accessibility and sitemap references.
- `lastmod` accuracy and sitemap-index target availability.
- Duplicate entries and unexpected URL variants.

## 5. Common failure patterns

- Including redirected or non-canonical URLs.
- Listing noindex or robots-blocked URLs as if they were intended indexable resources.
- Updating `lastmod` indiscriminately on every build.
- Exceeding protocol file or URL limits.
- Publishing a sitemap index that references missing or inaccessible child files.
- Assuming successful submission proves indexing.
