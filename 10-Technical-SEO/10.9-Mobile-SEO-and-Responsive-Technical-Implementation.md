# 10.11 — Structured Data Implementation & Validation

Structured data is a machine-readable representation of information associated with a page or resource. This topic covers technical implementation and validation. Conceptual meaning and entity modeling belong to Domain 09; visible search features and behavior belong to Domain 06.

## 1. Core concepts and mechanisms

Common web structured-data formats include JSON-LD, Microdata, and RDFa. Google supports these formats for Search structured data and generally recommends JSON-LD when a site's implementation can support it. Schema.org provides a shared vocabulary, but not every type or property is used for a Google Search feature. [1]

Select types and properties that accurately describe the page. Ensure markup reflects content visible to users and does not invent facts. Use stable identifiers and consistent entity references where appropriate. Keep markup aligned with page updates and canonical URL decisions. Avoid duplicate, conflicting, stale, or placeholder values. Follow specific feature documentation in addition to general guidelines.

Google's general guidelines require relevant, accurate, and non-misleading markup. Syntactically valid data can still violate quality rules or fail to qualify for a rich result. [2]

Separate validation into syntax/parsing; vocabulary and property correctness; required/recommended property completeness; consistency with visible content; crawlability of referenced resources; eligibility under current feature policies; and actual appearance, which remains at the search engine's discretion.

Validate representative templates and edge cases before rollout. Re-test after CMS, template, schema, or content changes. Domain 09 owns the semantic model; Domain 10 owns serialization, embedding, deployment, and technical validation; Domain 06 owns search appearance. Structured data is not a ranking shortcut.

## 2. Practical validation

Use representative URLs and templates, inspect the actual HTTP response and rendered output, document the environment and date, and retest after production deployment. A tool result is evidence about the test it performed, not a universal certification.

## 3. Limitations and ownership

Attribute search-engine-specific behavior to the engine that documents it. Distinguish technical validity from indexing selection, ranking, and search presentation. Use adjacent-domain links from the [Domain 10 index](README.md) to preserve canonical ownership.
