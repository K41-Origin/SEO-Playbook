# 10.2 — Website Architecture & URL Structure

Website architecture and URL structure define how resources are organized and addressed at the technical layer. They influence maintainability, consistent delivery, URL discovery, and management of large or parameterized URL inventories.

## 1. Core concepts and mechanisms

Distinguish conceptual information organization from technical implementation. Domain 09 owns semantic information architecture; Domain 11 owns internal-link architecture. This topic covers hosts, paths, routing rules, templates, URL patterns, query parameters, and resource endpoints.

Define consistent choices for scheme and host, HTTPS behavior, path conventions, trailing slashes, case sensitivity, normalization, query parameters, encoded characters, and missing or moved resources. Similar-looking URLs are not necessarily technically identical: frameworks, servers, proxies, and caches may treat variants differently.

Faceted navigation, session identifiers, tracking parameters, sorting, and pagination can multiply reachable URLs. Classify parameters by whether they change primary content, state, or merely tracking. Decide which variants should remain accessible, be canonicalized, redirected, or excluded from indexing; then test actual behavior.

Validate representative routes and templates, direct requests, parameter combinations, canonical output, status codes, and consistency between navigation and sitemap URLs. Watch for unbounded parameter combinations, inconsistent host/protocol variants, routes that work only after client-side navigation, and soft 404s.

Google documents that duplicate URL variants can create unnecessary crawling and that canonicalization signals help consolidate similar resources. That is provider-specific guidance, not a universal guarantee of canonical selection.

## 2. Practical validation

Use representative URLs and templates, inspect the actual HTTP response and rendered output, document the environment and date, and retest after production deployment. A tool result is evidence about the test it performed, not a universal certification.

## 3. Limitations and ownership

Attribute search-engine-specific behavior to the engine that documents it. Distinguish technical validity from indexing selection, ranking, and search presentation. Use adjacent-domain links from the [Domain 10 index](README.md) to preserve canonical ownership.
