# 10.6 — Indexability, Canonicalization & Duplicate URL Management

Indexability is the set of conditions under which a search engine can consider a resource for inclusion in its index. Site operators can provide directives and canonical hints, but search engines make their own indexing and canonical-selection decisions.

## 1. Core concepts and mechanisms

A URL can be crawlable but explicitly marked noindex. Conversely, a URL blocked from crawling may still be known through external references and could appear without a fetched page representation. These mechanisms must not be conflated.

For HTML pages, robots meta directives can communicate rules such as noindex; HTTP response headers such as X-Robots-Tag can apply rules to non-HTML resources including PDFs. These directives must be visible to the crawler. A robots.txt disallow rule can prevent the crawler from fetching the page and discovering the directive. [1]

Canonicalization is the process by which a search engine selects a representative URL from duplicate or substantially similar resources. Site owners can provide signals such as redirects, rel=canonical, and sitemap inclusion. These are signals, not commands. Google may select a different canonical URL. [2]

Common variants include HTTP/HTTPS, hostname, trailing-slash and case variants, tracking/session parameters, sorting/filtering/pagination, print and device variants, and duplicate CMS routes. Choose controls according to whether a variant should remain accessible, be consolidated, excluded from indexing, or removed. Redirects, canonical annotations, noindex, and access restrictions solve different problems.

Align redirects, canonical annotations, internal references, sitemap entries, and actual page content. Inspect source HTML and response headers; test canonical targets and representative parameter combinations; compare declared and observed canonical URLs.

## 2. Practical validation

Use representative URLs and templates, inspect the actual HTTP response and rendered output, document the environment and date, and retest after production deployment. A tool result is evidence about the test it performed, not a universal certification.

## 3. Limitations and ownership

Attribute search-engine-specific behavior to the engine that documents it. Distinguish technical validity from indexing selection, ranking, and search presentation. Use adjacent-domain links from the [Domain 10 index](README.md) to preserve canonical ownership.
