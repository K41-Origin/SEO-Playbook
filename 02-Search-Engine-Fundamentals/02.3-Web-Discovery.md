# 02.3 — Web Discovery

A search engine cannot crawl a URL it does not know exists. Before crawling comes discovery: the process of learning that a resource may be available.

This sounds obvious. Yet plenty of SEO advice jumps straight to crawling, indexing, and rankings—as if search engines receive a magical list of every page on the internet. They don't.

## 1. What Is Web Discovery?

**Web discovery** is the process through which a search engine becomes aware of URLs or other resources that may be candidates for further processing.

For web search, discovery helps build and maintain a collection of known URLs. It does not mean the search engine has fetched the resource, understood its content, or added it to an index.

Google explicitly describes URL discovery as finding out what pages exist on the web. It also states that there is no central registry of all web pages, so Google must continually look for new and updated pages. [1]

That gives us a critical distinction:

- **Discovered:** the search engine has learned about a URL.
- **Crawled:** a crawler has requested and retrieved the resource.
- **Processed:** the retrieved resource has been interpreted.
- **Indexed:** information from the resource has been added to a searchable index.

These are separate outcomes, not interchangeable SEO vocabulary. Discovery is the subject here; crawling is covered in [02.4 — Web Crawling](README.md#knowledge-structure).

## 2. Why Discovery Exists

The web is distributed. Websites publish content independently, URLs are created and changed continuously, and no single public directory contains every available page.

A search engine therefore needs ways to learn about resources over time. It can reuse what it already knows, follow references to other resources, and receive URL information from site owners or other sources.

Discovery is not a one-time event. Search engines need to find newly published resources and detect URLs that may have changed since they were last known. Google's documentation describes this as an ongoing effort to look for new and updated pages. [1]

**The important point:** a resource can exist publicly without being known to a particular search engine.

## 3. Main URL Discovery Sources

Search engines can learn about URLs through multiple paths. The following are documented Google discovery paths, with other mechanisms identified separately where relevant.

### 3.1 Previously Known URLs

A search engine can retain URLs it has encountered before. Those URLs may be revisited later, and previously known pages can lead to newly discovered resources when their links or content change.

Google says some URLs are known because it has already visited them. [1]

This means discovery is not limited to brand-new URLs. A URL already known to the system can remain part of its discovery and revisit processes.

The timing and selection of later visits belong to crawling and scheduling—not the discovery definition itself.

### 3.2 Links from Known Pages

Links create paths between resources. When a search engine encounters a link on a known page, it may learn the URL referenced by that link.

Google explicitly documents extracting links from known pages as one way it discovers new URLs. Its example is a category or hub page linking to a newly published article. [1]

This is why a site's navigational structure and internal links matter at a system level: they expose relationships and routes through which crawlers may encounter URLs.

Not every visible element that looks clickable is necessarily an extractable link. Google's documentation about crawling links recommends using crawlable HTML links with an `<a>` element and an `href` attribute. [2]

Do not confuse this with the deeper crawling question of how a crawler requests a discovered URL. Here, the relevant point is that links can expose URL references for discovery.

### 3.3 XML Sitemaps

A sitemap is a file that provides information about pages, videos, and other files on a site, including relationships and metadata about those resources.

Google says sitemaps help it discover URLs and can provide additional information such as when a page was last updated or alternate language versions. [3]

Sitemaps are especially useful when:

- A site is large and some pages may not be easy to reach through links.
- A site is new and has few external links pointing to it.
- A site contains rich media or other specialized content for which sitemap information can help. [3]

But a sitemap is not a command that forces a search engine to crawl every listed URL. Google explicitly says a sitemap does not guarantee that its URLs will be crawled or indexed. [3]

Treat it as a discovery aid and a source of hints—not an indexing cheat code.

### 3.4 Direct URL Submission and Change Notifications

Some search engines provide mechanisms for site owners to submit URLs or notify them when content changes.

For example, Bing recommends IndexNow as a way to notify participating search engines when URLs are added, updated, or deleted. Bing Webmaster Tools also documents URL Submission and Content Submission capabilities for direct submission to Bing, while recommending IndexNow where possible. Microsoft notes that these submission capabilities may be deprecated in the future. [4][5][6]

Protocol status must be distinguished from the submission capability itself: Microsoft announced that its legacy SOAP and POX protocols for Bing Webmaster APIs would be retired on August 31, 2026, and directs developers to the REST APIs. This protocol migration does not mean that URL Submission or Content Submission as capabilities were necessarily retired; Microsoft's current documentation continues to describe them. [7] As of this audit on November 15, 2026, the cited Microsoft Learn page still phrases the retirement in the future tense despite the announced date having passed. This document records Microsoft's published retirement notice; it does not independently confirm that every legacy endpoint has been decommissioned. Use the current REST API documentation and verify endpoint status before relying on older integrations. [7]

This is a useful distinction:

- A **URL submission** or **change notification** tells a search engine about a URL or a change.
- It does not itself prove that the resource has been crawled, indexed, or shown in results.

Google's documented discovery explanation highlights previously known URLs, links, and sitemaps. Do not assume that a mechanism supported by Bing or another engine is also supported by Google. The Bing Webmaster URL Submission API is a URL-notification product; it is distinct from the retired Bing Search APIs discussed in 02.7. [1][4][5][6]

### 3.5 External References

Links from other websites can expose a URL to a search engine that encounters those linking pages.

Google describes discovering new URLs by extracting links from known pages; its sitemap guidance also notes that a new site with few external links may be harder for crawlers to discover through previously crawled pages. [1][3]

This is a description of a discovery pathway, not a claim that every external link guarantees discovery or that link quantity alone determines whether a URL will be crawled or indexed.

## 4. Discovery Signals Are Not Guarantees

A URL can be submitted, listed in a sitemap, or linked from another page and still not be crawled.

Google explicitly states that it does not crawl every page it discovers. Its documentation identifies restrictions and access limitations as examples of reasons a discovered page may not be crawled. [1]

Likewise, Google says sitemap inclusion does not guarantee crawling or indexing. [3]

The correct mental model is:

`Discovery → Candidate for Crawling`

Not:

`Discovery → Guaranteed Crawl → Guaranteed Indexing → Guaranteed Ranking`

That second chain is wishful thinking dressed up as a workflow.

Discovery makes a resource known. Other systems and decisions determine what happens next.

## 5. Discovery vs. Crawling

These stages are related, but they answer different questions.

| Aspect | Web Discovery | Web Crawling |
|---|---|---|
| Core question | How did the search engine learn this URL exists? | Did the crawler request and retrieve the resource? |
| Main activity | Identify or receive URL references. | Fetch resources from URLs. |
| Typical inputs | Previously known URLs, links, sitemaps, supported submission mechanisms. | URLs selected for fetching, along with crawl controls and scheduling. |
| Typical output | Known or candidate URLs. | HTTP responses and retrieved resource content. |
| Does it guarantee the next stage? | No. | No guarantee of indexing. |

Google's public description places URL discovery before the act of visiting a page to crawl it. [1]

This distinction is important when diagnosing visibility problems. If a URL is unknown to a search engine, the issue is different from a URL that is already known but has not been fetched. Treating both situations as “Google isn't indexing my page” is too vague to be useful.

The detailed mechanics of requests, responses, crawler behavior, revisit decisions, and crawl scheduling belong in **02.4 — Web Crawling**.

## 6. A Simple Example

Imagine a website publishes a new article at:

`https://example.com/guides/search-architecture`

A search engine might learn about it through one or more routes:

1. The site's category page links to the new article.
2. The URL appears in the site's XML sitemap.
3. Another already-known website links to the article.
4. The site owner uses a URL submission or notification mechanism supported by that search engine.

These routes can make the URL known to the search engine. They do not establish that it has been fetched or indexed.

The example is illustrative; actual discovery paths and subsequent processing depend on the search engine.

## 7. What Discovery Means for SEO

Discovery is the first system-level condition for a URL to enter a crawler-based search pipeline. SEO cannot guarantee discovery, but site owners can avoid making important resources unnecessarily difficult to find.

At a conceptual level:

- Make important pages reachable through clear, crawlable internal links.
- Maintain an accurate sitemap when it provides useful coverage or update information.
- Use supported submission or notification mechanisms where the search engine offers them.
- Avoid assuming that publication alone makes a URL known to every search engine.
- Diagnose discovery separately from crawling and indexing.

These points follow from Google's documentation on links and sitemaps and Bing's documented URL discovery and notification mechanisms. [2][3][4][5]

The website-side implementation details—site architecture, internal linking strategy, XML sitemap configuration, and technical accessibility—belong in their respective SEO domains. This topic explains the search engine's discovery function, not a full technical SEO implementation guide.

## Summary

- Web discovery is how a search engine becomes aware of URLs or other resources that may be processed.
- There is no central registry containing every page on the web.
- Documented discovery paths include previously known URLs, links from known pages, and sitemaps.
- Some search engines also support direct URL submission or change-notification mechanisms; support differs by provider.
- Discovery does not mean crawling, processing, indexing, or ranking has happened.
- A URL being submitted or listed in a sitemap does not guarantee that it will be crawled or indexed.

**Bottom line:** discovery gets a URL onto the search engine's radar. It does not give that URL a free pass through the rest of the pipeline.
